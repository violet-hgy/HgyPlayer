## 1. 将 FFmpeg 接入 Qt/CMake 工程

### 问题

需要在 Qt 工程中链接头文件、导入库，并保证运行时能找到 DLL。

### 解决方法

在 `CMakeLists.txt` 中：

1. 设置 `FFMPEG_ROOT` 指向解压目录。
2. `target_include_directories` 加入 `include/`。
3. MinGW 链接 `lib/*.dll.a`，MSVC 链接 `lib/*.lib`。
4. `POST_BUILD` 把 `bin/` 下 DLL 复制到可执行文件目录。
5. 播放器音频还需 Qt **Multimedia** 模块：

```cmake
find_package(Qt6 REQUIRED COMPONENTS Widgets Multimedia)
target_link_libraries(HgyPlayer PRIVATE Qt6::Widgets Qt6::Multimedia)
```

修改 CMake 后，在 Qt Creator 中需 **重新运行 CMake** 再编译。

本项目 FFmpeg 目录：`ffmpeg-master-latest-win64-lgpl-shared/`（含 `bin/`、`include/`、`lib/`）。

## 2. 编译错误：`qBound` 重载歧义

### 问题

```text
error: call of overloaded 'qBound<qint64>(int, qint64&, int)' is ambiguous
```

### 原因

`qBound(low, value, high)` 是 Qt 的区间夹取函数，等价于把 `value` 限制在 `[low, high]`。

当参数类型混用（例如 `0` 为 `int`，`ms` 为 `qint64`，`maximum()` 为 `int`）时，模板/重载匹配会产生歧义。

### 解决方法

统一类型后再调用：

```cpp
const qint64 maxPos = m_seekSlider->maximum();
const qint64 clamped = qBound(qint64(0), ms, maxPos);
m_seekSlider->setValue(static_cast<int>(clamped));
```

## 3. 播放器没有声音

### 问题

画面能播，但没有声音。

### 原因（两处）

1. **`QAudioSink` 放在了解码 Worker 线程**  
   Worker 的 `runLoop()` 长时间阻塞，占满该线程，音频设备缺少正常事件循环，在 Windows 上经常完全无声。

2. **重采样（swr）初始化过早**  
   打开文件时，codec 上下文里的 `sample_fmt` / 声道布局经常还是未就绪（`NONE`）。此时 `swr_init` 失败，旧逻辑会静默关闭音频通路。

### 解决方法

1. **音频设备放在主线程**  
   - Worker 只负责解码并产出 PCM  
   - 通过线程安全队列 + 主线程 `QTimer` 喂给 `QAudioSink`

2. **首帧懒加载 swr**  
   - 等第一帧真实 `AVFrame` 再按帧的 format / sample_rate / ch_layout 初始化 `SwrContext`

3. Seek / Stop 时清空 PCM 队列与音频缓冲，避免旧数据干扰。

相关实现：`media/FFmpegPlayer.cpp`（主线程音频泵 + `ensureSwrFromFrame`）。

## 4. Seek 后视频无法继续播放 / 进度条回跳

### 问题

1. 拖动进度条 Seek 之后，画面卡住或很久不动。  
2. Seek 后时间/进度条又跳回正在播放的旧进度。

### 原因

**卡死：** Seek 后解码器从更早关键键帧开始解。若仍用 Seek 点之前的帧 PTS 更新时钟，时钟被拉回，后续帧会算出巨大延时，`waitForPts` 长时间 sleep。

**回跳：** Seek 通过队列异步执行。松手后 `m_sliderPressed` 已为 false，Worker 在真正跳转前仍发出旧的 `positionChanged`，UI 立刻把滑块和时间拉回旧进度。

### 解决方法

1. Seek 后设置 `m_discardUntilPtsMs`，丢弃目标时间之前的帧。  
2. `updateClock` 禁止过期 PTS 回拨；seek 请求未执行时不再抛旧进度。  
3. `m_seekSerial`：等待中的旧帧一律丢弃。  
4. Seek 投递策略：
   - **播放中**：`requestSeek()` 直接置标志（因 `runLoop` 占满线程，Queued 槽无法执行）  
   - **空闲时**：`applySeek` 投递到 Worker 线程执行  
5. Prefer `avformat_seek_file`，失败再回退 `av_seek_frame`。  
6. UI / 门面层使用 `m_pendingSeekMs` / `seekingToMs`：在进度接近目标前忽略过期 `positionChanged`。

### 分层回顾

```text
UI (MainWindow)
  └── FFmpegPlayer（主线程 API + 音频设备）
        └── PlayerWorker（解码线程）
              ├── Demux: av_read_frame
              ├── Decode: video / audio
              ├── Sync: 媒体时钟 + waitForPts
              └── Seek: flush + 丢弃过期帧
```
